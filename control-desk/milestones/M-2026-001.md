# Milestone Record: File-Based Control Desk Foundation

## Mission

Define the initial repository-native storage model for the STS Control Desk so milestone records can be inspected, reviewed, and indexed later without changing their meaning.

### Why this matters

The Control Desk needs a transparent source of truth before a dashboard or database is introduced. This milestone establishes that source without adding execution or approval power.

## Current State — Observe

- The repository contains the canonical STS method, templates, and checklists.
- The Control Desk state machine and control-gate specification exists in `CONTROL-DESK.md`.
- No application or database exists in the repository.
- Git checkpoint: not yet created for this milestone.

### Evidence collected

- `git status --short --branch`
- `git diff --check`
- Inspection of `METHOD.md`, `README.md`, templates, and checklists.

## Problem — Understand

### Confirmed facts

- Existing records are Markdown templates without a common machine-readable record layout.
- The future Control Desk needs stable IDs and links between milestones, approvals, risks, evidence, and verification.

### Reasonable inferences

- Markdown with YAML front matter is sufficient for the initial repository-native source of truth.
- A later SQLite index can be derived from the same logical fields.

### Unknowns

- The scale at which SQLite becomes necessary.
- The eventual user interface and hosting environment.

### Root problem

The method defines controlled work, but the repository does not yet provide a canonical file-based record structure that a future desk can reliably inspect.

## Goal and Scope

### Goal

Provide a documented file-based record layout, logical schema, first milestone record, and read-only validator.

### In scope

- `control-desk/README.md`
- `control-desk/schema.md`
- `control-desk/milestones/M-2026-001.md`
- `control-desk/validate.py`
- Links from the main Control Desk specification and README.

### Out of scope

- SQLite storage
- Web or mobile UI
- Automatic approval or execution
- Deployment or external publication
- Git commit or push
