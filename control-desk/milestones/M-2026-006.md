# Milestone Record: Read-Only SQLite Projection

## Mission

Implement a manually invoked, read-only SQLite indexer against an explicit STS project registry so historical and current milestones can be queried across projects.

## Scope

- Explicit JSON project registry.
- SQLite schema for projects, records, links, index runs, and errors.
- Source commit, dirty-state, content-hash, and indexing-time provenance.
- Manual invocation with `:memory:` dry-run support.
- Historical records retained as active or inactive indexed records.

## Out of scope

- Dashboard UI
- Automatic discovery or scheduled synchronization
- Editing source records through SQLite
- Approval, execution, deployment, or external publication

## Risks

- [R-2026-002](../risks/R-2026-002.md) — cross-project index misrepresents source state.

## Acceptance Criteria

- [x] The registry explicitly identifies the repository to read.
- [x] The indexer reads only registered project `control-desk/` paths.
- [x] SQLite stores source provenance and freshness fields.
- [x] Historical records remain queryable and are not overwritten by current status.
- [x] Invalid or unavailable sources are recorded as errors.
- [x] The indexer can run against an in-memory database without source writes.
