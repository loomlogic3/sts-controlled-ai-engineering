# Milestone Record: Dual-Deployment Control Desk Architecture

## Mission

Define a safe architecture for offering STS Control Desk as both hosted SaaS and self-hosted/local software while preserving project-repository authority and human control.

## Goal and Scope

### In scope

- Tenant, organization, project, and user boundaries.
- Hosted versus self-hosted deployment responsibilities.
- Repository connector and synchronization model.
- Authentication, authorization, encryption, audit, retention, export, and deletion requirements.
- Freshness, invalidation, outage, and recovery behavior.
- Migration path from the current local SQLite/HTML projection.
- Acceptance criteria for a future architecture or prototype milestone.

### Out of scope

- Deploying a public service.
- Selecting a cloud provider or purchasing infrastructure.
- Automatic sync or repository writes.
- Automatic approval, execution, deployment, or scope expansion.
- Ingesting full repository contents without separate approval.

## Risks

| Risk | Impact | Control |
|---|---|---|
| Tenant isolation failure | Confidential project data could cross organization boundaries. | Require explicit tenancy model, isolation tests, and security review before implementation. |
| Hosted projection becomes mistaken for authority | Users could act on stale or incomplete data. | Preserve source links, freshness state, invalidation rules, and visible derived-data labeling. |
| Connector overreach | A connector could read or write beyond approved boundaries. | Least-privilege, read-only connectors by default and explicit repository scopes. |
| SaaS availability or provider dependency | Teams could lose access to control history. | Export, self-hosted mode, rebuildability, backups, and recovery testing. |

## Acceptance Criteria

- [ ] Hosted and self-hosted trust boundaries are documented.
- [ ] Tenant and project isolation requirements are testable.
- [ ] Connector permissions and synchronization states are defined.
- [ ] Security, privacy, retention, export, and deletion controls are defined.
- [ ] The migration path from local projection is reversible and evidence-backed.
- [ ] A separate implementation milestone and approval boundary are identified.
